## Шифрование: этап 2 (v0.9)

Зашифрованными беседами стало проще пользоваться и труднее их потерять. Пользователю почти ничего не нужно делать: один раз сохранить ключ и нажимать «Да» на старом устройстве, когда входите с нового.

**Ключ восстановления и история**

- При первой зашифрованной беседе появляется окно «Сохраните ключ восстановления» (скачать, скопировать или позже). Если потеряны все устройства, ключ возвращает переписку: браузер хранит на сервере копию истории, зашифрованную ключом, которого у сервера нет.
- Показать ключ снова, ввести его на новом устройстве или, если потеряно всё вместе с ключом, сбросить ключи шифрования — в «Настройки → Устройства».

**Подтверждение нового устройства**

- Вошли с нового браузера — в зашифрованной беседе «Подтвердить с другого устройства». На старом появляется «Новый вход: … Это вы?» и одинаковые 4 эмодзи на обоих экранах; «Да» — и новое устройство получает всю историю, без ввода ключей.
- Сравнение эмодзи защищает от подмены устройства: сервер не может подобрать свои ключи так, чтобы эмодзи совпали.

**Проверка собеседника — один раз**

- Код безопасности теперь считается от ключа пользователя: сверили один раз — и новые устройства, которые человек подтвердил сам, не требуют повторной проверки.
- Предупреждение остаётся только о неподтверждённом устройстве и о сбросе ключей.

**Ещё в зашифрованных беседах**

- Реакции шифруются: сервер знает, что человек отреагировал, но не каким эмодзи.
- Поиск — на устройстве, по расшифрованным сообщениям (поле поиска в шапке беседы).
- Из фото перед шифрованием вырезаются метаданные: камера, геометка, комментарии.
- Сообщения, отправленные до подключения устройства, сворачиваются в одну строку вместо стены «недоступно».

**Важно**

- Шифрование по-прежнему помечено «бета»: независимой проверки ещё не было. Нашли уязвимость — сообщите приватно на GitHub: Security → Report a vulnerability.
- Как всё устроено — [docs/encryption.md](https://github.com/vogster/ChinchiChat/blob/main/docs/encryption.md).

## Обновление с 0.8.x

```bash
# в .env: CHINCHI_VERSION=0.9.0 (или возьмите новый docker-compose.yml из релиза)
docker compose pull && docker compose up -d
```

- Миграции применяются сами. Первое устройство пользователя, открывшее новую версию, само создаст ключ пользователя и ключ восстановления; остальные его устройства нужно один раз подтвердить с первого (или ключом восстановления), иначе собеседники увидят их как неподтверждённые.
