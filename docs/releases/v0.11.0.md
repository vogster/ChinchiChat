## Проще ставить и обслуживать (v0.11)

Промежуточный релиз на пути к 1.0: Chinchi теперь ставится на одно доменное имя, а для резервных копий появились готовые скрипты.

**Один домен вместо трёх**

- Достаточно одного DNS-имени: на нём приложение, файлы (путь `/chinchi/`) и голос (`/livekit/`), с одним HTTPS-сертификатом.
- Файлы на основном домене отдаются в «песочнице» и не могут выполниться как приложение. Отдельные домены для файлов и голоса (`FILES_DOMAIN`, `VOICE_DOMAIN`) остались по желанию.

**Резервные копии**

- `backup.sh` собирает в один архив базу, файлы и версию Chinchi. Сервер на время копирования останавливается на несколько секунд.
- `restore.sh` возвращает архив на эту же или на чистую машину с тем же `.env`. В более старую версию он восстанавливать откажется.
- Цикл «бэкап → чистая установка → восстановление» проверен. Подробно — в [руководстве](https://github.com/vogster/ChinchiChat/wiki/Обновление-и-резервные-копии).

**В приложении**

- Подсказки при вводе: `@` предлагает людей, роли и `@everyone`, а `#` — каналы. Стрелки выбирают, Enter или Tab вставляет.
- У зашифрованных бесед и звонков появилась пометка «бета»: шифрование ещё не проходило независимой проверки.
- На сообщения зашифрованных бесед больше нельзя пожаловаться: сервер не видит их текста, и модераторам нечего было бы разбирать.
- Свои эмодзи в цитате ответа теперь видны как `:название:`, а не как служебный текст.

**Документация**

- [Wiki](https://github.com/vogster/ChinchiChat/wiki) с руководством по всем возможностям: для пользователей, модераторов, администраторов и разработчиков.
- Новый README со скриншотами.

## Обновление с 0.10.x

```bash
# в .env: CHINCHI_VERSION=0.11.0
docker compose pull && docker compose up -d
curl -fsSLO https://github.com/vogster/ChinchiChat/releases/download/v0.11.0/backup.sh
curl -fsSLO https://github.com/vogster/ChinchiChat/releases/download/v0.11.0/restore.sh
chmod +x backup.sh restore.sh
```

- Существующие установки с тремя доменами продолжают работать: если в `.env` заданы `FILES_DOMAIN` и `VOICE_DOMAIN`, они используются как раньше.
- Чтобы перейти на один домен, очистите `FILES_DOMAIN` и `VOICE_DOMAIN` в `.env` и выполните `docker compose up -d`. Ссылки на файлы, которые браузеры успели запомнить, перестанут работать, новые сервер выдаст сам. Старые DNS-записи потом можно удалить.
- Миграции применяются сами.
