## Безопасность, удаление зашифрованных бесед и своя шапка окна (v0.18.1)

Обновляются сервер, веб-клиент и приложение для компьютера. Миграций базы нет. Большая часть выпуска — исправления по ревью безопасности 0.18.

**Безопасность**

- Вход по QR теперь подтверждается числом: после сканирования новое устройство показывает число, а на телефоне его нужно выбрать из нескольких. Код, который вам прислали чужие люди, так не сработает. О каждом входе по QR приходит письмо и уведомление «Новый вход» в открытых сессиях.
- Ссылка подтверждения входа в сообщении больше не кликабельна: чат сворачивает её в предупреждение, которое можно развернуть.
- Назначение роли больше не выдаёт прав, которых нет у того, кто назначает, и не достаёт до участников выше него. На сервере — не больше 250 ролей.
- Первый администратор из `INITIAL_ADMIN_EMAIL` становится администратором только после подтверждения почты. Без SMTP ссылка подтверждения пишется в лог сервера (`FIRST ADMIN LINK`).
- Запрос в друзья по id, как и по имени, требует подтверждённую почту, если её требует инстанс.
- Замена ключа шифрования пользователя (сброс ключей) спрашивает пароль и код 2FA, а резервная копия истории заменяется только вместе с ключом.
- Экспорт данных спрашивает пароль и код 2FA и отдаётся по одноразовому билету. Файлы архива идут из хранилища потоком, одновременно собирается не больше двух экспортов.
- Шлюз реального времени закрывает клиентов, которые не успевают читать (больше 4 МБ в очереди), и ограничивает число соединений: 10 на пользователя и 100 на адрес. Лимит на адрес задаёт `GATEWAY_MAX_CONNECTIONS_PER_ADDRESS` — поднимите его, если много людей ходят через один NAT.
- Caddy отдаёт хранилищу только бакет с файлами и не передаёт ему cookie сессии.
- Скачивание файлов несёт токен сессии только на свой сервер и обрывается, если файл больше заявленного. «Сохранить как» в приложении получает только имя файла, без пути, а невидимые символы направления текста из имён убираются.

**Зашифрованные беседы**

- Зашифрованную беседу можно удалить у всех: в ЛС — любой из двоих, в группе — владелец. Сообщения, файлы и ключи уходят с сервера и со всех устройств. Новая зашифрованная беседа с тем же человеком начинается с чистого листа.
- Клиент больше не верит серверу на слово. Если беседа, которую устройство видело зашифрованной, вдруг пришла обычной, писать в неё нельзя: так сообщение не уйдёт открытым текстом. Плашка объясняет, что прежние сообщения остались зашифрованными, и предлагает «Убрать беседу». Старую историю по-прежнему можно читать, сообщения без шифрования помечены, а беседа отмечена в списке ЛС. Если сервер снова отдаст её зашифрованной, всё вернётся как было.
- Если вы просили зашифрованную беседу, а сервер вернул обычную, она не откроется.
- В зашифрованную группу попадают только те, кого добавил кто-то из участников. Плашка показывает, кто кого добавил.
- Исправлен бесконечный цикл, в котором устройство добавлялось в зашифрованную ЛС и удалялось из неё по кругу.
- У скачивания зашифрованных файлов есть прогресс с отменой: «Загрузка N %», затем «Расшифровка…».

Подробно все случаи описаны в [docs/encryption.md](../encryption.md) и в вики, страница «Зашифрованные беседы».

**Пароли**

- Во всех полях пароля есть глазок: вход, регистрация, новый пароль по ссылке, смена пароля, 2FA и окна подтверждения ([#51](https://github.com/vogster/ChinchiChat/issues/51)).
- Окна подтверждения (смена email, экспорт, удаление учётной записи, отключение 2FA, новые коды восстановления, сброс ключей) спрашивают сначала пароль, потом код 2FA, как при входе. Шаги сменяются слайдом.

**Приложение для компьютера**

- На Windows и Linux окно больше не носит серую системную рамку: заголовок рисует само приложение, в цвете темы, со скруглениями и тенью системы. Слева — стрелки «назад» и «вперёд» по истории, по центру — название окна со счётчиком непрочитанного, справа — тонкие кнопки «свернуть», «развернуть» и «закрыть». Крестик по-прежнему прячет приложение в трей, если так настроено.
- Шапку можно таскать, двойной щелчок разворачивает окно, края окна по-прежнему тянутся мышью.
- На macOS рамка остаётся системной: «светофоры» родные, заголовок скрыт, шапка приложения лишь оставляет под них место.
- Микрофон и камера включаются сразу по нажатию кнопки: полоски «localhost хочет использовать микрофон» от встроенного браузера больше нет, как в Discord. Системный запрос macOS к самому приложению остаётся.
- Аватарки, значки серверов, баннеры, эмодзи сервера и картинки превью теперь показываются и в приложении: раньше оно искало их не на сервере, а у себя, и вместо картинки был пустой квадрат.
- Вложения тоже работают в приложении: картинки и их превью, голосовые, файлы на скачивание и зашифрованные файлы приложение получает через API с вашей сессией, а не по ссылке, которой встроенный браузер не мог предъявить вход.
- Скачивание в приложении — через системное окно «Сохранить как», которое открывается в «Загрузках»: так сохраняются файлы из сообщений, картинки из просмотра, расшифрованные файлы, ключ восстановления и коды 2FA. Раньше на Windows это делал встроенный браузер со своей всплывашкой «Загрузки», а на macOS и Linux кнопка молчала. У скачивания есть прогресс и отмена.
- Файлы можно перетаскивать в чат.

## Обновление с 0.18.0

Приложение для компьютера предложит обновление само. Для сервера возьмите из релиза новый `docker-compose.yml` (в нём новая переменная `GATEWAY_MAX_CONNECTIONS_PER_ADDRESS`); в `.env` её можно не задавать — по умолчанию 100:

```bash
./backup.sh
# в .env: CHINCHI_VERSION=0.18.1
docker compose pull && docker compose up -d
```

Если администратора на инстансе ещё нет, учётная запись с `INITIAL_ADMIN_EMAIL` станет им только после подтверждения почты; уже назначенных администраторов это не касается.
