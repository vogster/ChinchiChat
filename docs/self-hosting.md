# Установка Chinchi на свой сервер

Chinchi разворачивается одним `docker compose` на одной машине: сервер API и realtime-шлюз, web-клиент, PostgreSQL, Valkey, S3-хранилище RustFS, LiveKit для голоса и видео и Caddy, который сам получает HTTPS-сертификаты. Образы готовые (GitHub Container Registry), на сервере нужны только два файла — `docker-compose.yml` и `.env`; клонировать репозиторий и что-то собирать не нужно.

## Что нужно

- Linux-сервер (x86-64) с Docker Engine 24+ и плагином Compose v2. Для небольшого сообщества хватит 2 vCPU и 4 ГБ памяти; голос и видео нагружают прежде всего сеть и процессор LiveKit.
- Три DNS-имени, указывающие на сервер (записи A и/или AAAA), например:
  - `chat.example.com` — приложение и API;
  - `files.chat.example.com` — файлы (отдельный домен, чтобы загруженное пользователями никогда не исполнялось на домене приложения);
  - `voice.chat.example.com` — сигнальный канал LiveKit.
- Открытые порты: TCP 80 и 443 (Caddy), TCP 7881 и UDP 7882, 3478 (медиа LiveKit и встроенный TURN).
- Почтовый ящик с SMTP — для подтверждения email и сброса пароля (необязательно: без SMTP письма только пишутся в лог).

## Установка

```bash
mkdir chinchi && cd chinchi
curl -fsSLO https://github.com/vogster/ChinchiChat/releases/latest/download/docker-compose.yml
curl -fsSL -o .env https://github.com/vogster/ChinchiChat/releases/latest/download/env.example
```

Заполните `.env`: три домена и секреты. Секреты удобно сгенерировать так:

```bash
openssl rand -base64 32
```

`LIVEKIT_API_SECRET` должен быть не короче 32 символов. Затем:

```bash
docker compose up -d
```

Миграции базы применяются при старте сервера, бакет хранилища и его CORS создаются автоматически. Когда все контейнеры здоровы (`docker compose ps`), откройте `https://chat.example.com` и зарегистрируйтесь. Администратором инстанса станет учётная запись с адресом из обязательной переменной `INITIAL_ADMIN_EMAIL` (с ним можно зарегистрироваться, даже если регистрация закрыта) — но только пока на инстансе нет ни одного администратора: позже этот адрес никаких прав не даёт. В разделе «Настройки → Администрирование» можно закрыть регистрацию или перевести её на приглашения (ссылки создаются там же), ограничить число серверов на человека, найти и заблокировать пользователя, удалить сервер. `REGISTRATION_MODE` задаёт только значение по умолчанию.

## Обновление

Версия Chinchi зафиксирована: скачанный `docker-compose.yml` запускает тот релиз, с которым он вышел, и сам по себе не обновится. Чтобы перейти на новый релиз, укажите его в `.env` и перезапустите:

```bash
# в .env: CHINCHI_VERSION=0.4.0
docker compose pull && docker compose up -d
```

Перед обновлением прочитайте заметки к релизу на GitHub — там будет сказано, если нужно взять и новый `docker-compose.yml`. Данные лежат в именованных томах Docker (`postgres-data`, `rustfs-data`, `valkey-data`, `caddy-data`) и при обновлении сохраняются.

## Сборка из исходников

Для разработчиков и тех, кто не хочет готовых образов:

```bash
git clone https://github.com/vogster/ChinchiChat.git && cd chinchi.chat
cp deploy/.env.example deploy/.env   # и заполнить
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.build.yml up -d --build
```

## Резервные копии

Достаточно копировать базу и хранилище файлов; Valkey хранит только временное состояние (онлайн-статусы, голос, лимиты).

```bash
docker compose exec -T postgres pg_dump -U chinchi chinchi | gzip > chinchi-$(date +%F).sql.gz
docker run --rm -v chinchi_rustfs-data:/data -v "$PWD":/backup alpine tar czf /backup/chinchi-files-$(date +%F).tar.gz -C /data .
```

## Голос и видео

- Браузеры подключаются к LiveKit по `wss://VOICE_DOMAIN`, а медиа идёт напрямую по UDP 7882. Если UDP закрыт, LiveKit переходит на TCP 7881 или встроенный TURN (UDP 3478).
- LiveKit определяет публичный адрес сервера через STUN (`use_external_ip` в `LIVEKIT_CONFIG` внутри `docker-compose.yml`). Если у сервера несколько адресов или он за NAT провайдера, задайте адрес явно параметром `rtc.node_ip` там же.
- TURN поверх TLS (для очень строгих корпоративных сетей) по умолчанию не настроен: он требует отдельного домена с сертификатом, см. документацию LiveKit.

## Мониторинг

Сервер отдаёт метрики Prometheus на отдельном порту `9464` (`/metrics`): время ответа API по маршрутам, открытые соединения шлюза, отправленные и опубликованные события, фоновые задачи, а также стандартные метрики Node.js (память, CPU, задержка цикла событий). Порт открыт только внутри сети Docker и наружу не публикуется — добавьте свой Prometheus в ту же сеть и укажите цель `server:9464`. Вне Docker метрики включаются переменной `METRICS_PORT` и по умолчанию слушают только `127.0.0.1` (`METRICS_HOST`).

## Если что-то не работает

- `docker compose logs server` — сервер пишет в лог неверные переменные окружения (имя переменной, без значения).
- Сертификаты не выдаются — проверьте, что все три имени указывают на сервер и порт 80 доступен снаружи.
- Нет звука, хотя голосовой канал подключается — почти всегда это закрытые UDP-порты 7882 и 3478.
- Загрузки файлов падают — `FILES_DOMAIN` должен открываться снаружи и указывать на этот же сервер.
