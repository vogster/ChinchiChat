# Чек-лист безопасности

Проверяется перед каждым релизом (и после крупных изменений) — вручную, на свежей установке из `deploy/docker-compose.yml`. Автоматические тесты покрывают логику прав и защиты; этот список — о том, что видно только на живом инстансе, и о том, что легко сломать незаметно.

Как пользоваться: пройдите разделы, отмечая пункты в копии этого файла (или в issue релиза). Всё, что не прошло, — блокер релиза, если не записано осознанно в TODO с причиной.

## 1. Развёртывание

- [ ] Наружу открыты только 80/443 (Caddy) и порты LiveKit (7881/tcp, 7882/udp, 3478/udp). `nmap -p- <host>` не показывает Postgres, Valkey, RustFS, сервер API (3000) и метрики (9464).
- [ ] HTTPS везде, HTTP перенаправляется; `curl -sI https://<домен>` показывает HSTS.
- [ ] Файлы пользователей отдаются с **отдельного домена** (`FILES_DOMAIN`), не с домена приложения: чужой HTML/SVG не выполняется в origin приложения.
- [ ] Пароли и ключи в `.env` сгенерированы (не значения из примера), `.env` не лежит в публичном месте, права `600`.
- [ ] `INITIAL_ADMIN_EMAIL` задан, если сервер открыт в интернет до регистрации администратора.
- [ ] `TRUST_PROXY` соответствует схеме (в compose — только Caddy видит сервер).
- [ ] Логи сервера не содержат токенов: `docker compose logs server | grep -E 'webhooks/[0-9]+/[^[]|interactions/[0-9]+/[^[]'` пусто.

## 2. Заголовки и браузер

- [ ] На страницах приложения есть `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, запрет встраивания во фреймы (`frame-ancestors 'none'` или `X-Frame-Options: DENY`).
- [ ] Файлы пользователей отдаются с `nosniff` и `Content-Disposition`: HTML/SVG скачиваются, а не открываются; картинки открываются inline только после проверки сигнатуры.
- [ ] Cookie `chinchi_session`: `HttpOnly`, `Secure`, `SameSite=Lax`.

## 3. Аккаунты и сессии

- [ ] Неверный пароль, несуществующий логин и забаненный аккаунт дают одинаковый ответ и время (нет перечисления пользователей).
- [ ] После 10 неудачных входов за 15 минут вход блокируется; лимит действует и при смене IP через `X-Forwarded-For` (подставить заголовок вручную).
- [ ] Сброс пароля: ссылка одноразовая, истекает, после сброса все сессии завершаются.
- [ ] 2FA: код нельзя использовать дважды; коды восстановления одноразовые; перебор кодов ограничен.
- [ ] Выход и «завершить все сессии» закрывают открытые соединения шлюза (вкладка в другом браузере разлогинивается).
- [ ] Удаление учётной записи требует пароль, не работает для владельца серверов и последнего администратора.

## 4. CSRF и CORS

- [ ] Изменяющий запрос с cookie и чужим `Origin` → 403 (`CSRF_ORIGIN_MISMATCH`), без `Origin` и с cookie → 403.
- [ ] WebSocket шлюза с cookie и чужим `Origin` не устанавливается.
- [ ] API не отвечает `Access-Control-Allow-Origin: *` для запросов с cookie.

## 5. Права (под двумя аккаунтами)

- [ ] Не участник сервера получает 404 на любой id этого сервера: сервер, канал, сообщение, вложение, роль, эмодзи, вебхук.
- [ ] Скрытый канал (запрет VIEW_CHANNEL) не виден нигде: список каналов, поиск, упоминания, закрепления, треды, превью ссылок, копии объявлений, события шлюза (сообщения, набор текста, реакции).
- [ ] Нельзя выдать себе или роли права, которых нет у себя; нельзя управлять ролью выше своей.
- [ ] Бан: забаненный не возвращается по инвайту, его бот не добавляется обратно; тайм-аут запрещает писать, реагировать, говорить в голосе, вызывать команды.
- [ ] ЛС: заблокированный не может написать и позвонить; настройка «только друзья» соблюдается.
- [ ] Боты не могут: создавать серверы, принимать инвайты, дружить, писать в ЛС, становиться владельцами и администраторами.
- [ ] Администратор инстанса не может снять права с последнего администратора и удалить сам себя через админку.

## 6. Файлы и сеть

- [ ] Загрузка файла больше `UPLOAD_MAX_BYTES` отклоняется хранилищем (размер подписан в URL).
- [ ] Файл с подменённым типом (HTML как `image/png`) не открывается inline.
- [ ] У отправленной фотографии нет EXIF/GPS: скачать оригинал и проверить `exiftool`.
- [ ] Превью ссылок не ходит во внутреннюю сеть: ссылки на `http://127.0.0.1`, `http://169.254.169.254`, `http://[::1]`, `http://10.x`, редирект на них и домен, резолвящийся во внутренний адрес, превью не дают.
- [ ] Огромная картинка (decompression bomb, 30000×30000) не роняет сервер и воркер превью.

## 7. Интеграции

- [ ] URL вебхука показывается один раз; удалённый вебхук отвечает 404.
- [ ] Ответ на слэш-команду возможен один раз и только 15 минут; после того как бота выгнали, ответ не проходит.
- [ ] Подписка на канал объявлений пропадает, если создатель подписки потерял доступ к источнику.

## 8. Нагрузка и отказоустойчивость

- [ ] `pnpm load` (см. PLAN §4.9) на целевом железе: доставка p95 < 150 мс, READY p95 < 2 с, без ошибок.
- [ ] Падение процесса сервера (`docker kill`): пользователи уходят в offline в течение ~2 минут, после перезапуска клиенты переподключаются сами.
- [ ] Недоступность хранилища не роняет API (загрузки отключаются с понятной ошибкой).

## 9. Зависимости

- [ ] `pnpm audit --prod` без critical/high — проверяется в CI на каждом коммите; исключения записаны с причиной.
- [ ] Образы релиза прошли скан Trivy в `release.yml` (CRITICAL/HIGH с исправлением блокируют релиз), digest базовых образов в Dockerfile и compose обновлены через Dependabot.
- [ ] Аттестация происхождения образов проверяется: `gh attestation verify oci://ghcr.io/vogster/chinchi-server:<версия> --owner vogster` (и для `chinchi-web`).
