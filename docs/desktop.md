# Chinchi для компьютера

Настольное приложение — это тот же веб-клиент в оболочке [Tauri 2](https://v2.tauri.app): окно системного webview (WebView2 на Windows, WKWebView на macOS, WebKitGTK на Linux) и небольшой слой на Rust для того, чего вкладке браузера не дано: трей, автозапуск, глобальное сочетание клавиш, бейдж на значке, обновления. Код — `apps/desktop` (оболочка) и `apps/web/src/desktop` (вход и всё, что приложение знает о Tauri).

## Установка и первый запуск

Сборки для Windows (`.msi`, `.exe`), macOS (`.dmg`, universal) и Linux (`.AppImage`, `.deb`, `.rpm`) лежат в [релизах](https://github.com/vogster/ChinchiChat/releases) рядом с файлами сервера. Сборки пока не подписаны сертификатами Microsoft и Apple: Windows SmartScreen и Gatekeeper предупредят при первом запуске («Подробнее → Выполнить в любом случае»; на macOS — правый клик → Открыть). Подпись обновлений — отдельный механизм, он работает: приложение проверяет подпись каждого обновления ключом, вшитым в сборку.

При первом запуске приложение спросит адрес вашего сервера Chinchi — тот же, что вы открываете в браузере. Оно проверит, что там действительно Chinchi, и запомнит адрес; сменить его можно в «Настройки → Приложение → Сменить сервер» (это выход из учётной записи на прежнем сервере).

## Чем отличается от браузера

- **Вход** идёт по токену (bearer), а не по cookie: сессия хранится в файле настроек приложения (`settings.json` в каталоге данных приложения), запросы уходят через HTTP-плагин Tauri, поэтому CORS и Origin webview'а серверу не мешают. Сервер со своей стороны допускает такие запросы и подключения шлюза без проверки Origin — у них нет cookie, которую можно было бы подделать.
- **Уведомления** — системные, через плагин уведомлений (тот же `Notification` API, что в браузере); включаются в «Настройки → Уведомления».
- **Бейдж непрочитанного** на значке в доке/панели задач повторяет счётчик вкладки.
- **Трей**: значок с меню «Открыть» и «Выйти»; по умолчанию крестик окна прячет приложение в трей (настройка «Сворачивать в трей при закрытии окна»).
- **Автозапуск** вместе с системой — настройка «Запускать вместе с системой».
- **Своя шапка окна**: на Windows и Linux окно создаётся без системной рамки (`decorations: false`), заголовок с кнопками «назад/вперёд», названием страницы и кнопками окна рисует приложение (`src/desktop/title-bar.tsx`); перетаскивание и разворот двойным щелчком даёт атрибут `data-tauri-drag-region`, кнопки идут через `Shell.window`. На macOS рамка остаётся системной со скрытым заголовком (`tauri.macos.conf.json`: `titleBarStyle: Overlay`), «светофоры» родные, шапка лишь оставляет под них место. Права на окно — в `capabilities/default.json`: без них кнопки молча не работают.
- **Push-to-talk**: глобальное сочетание клавиш (например `Ctrl+Shift+V`), пока оно зажато, микрофон в голосовом канале включён, даже если окно не на переднем плане. Задаётся в «Настройки → Приложение»; перед сохранением приложение проверяет, что сочетание можно занять.
- **Обновления**: через несколько секунд после запуска приложение спрашивает у GitHub, нет ли новой версии (`latest.json` в последнем релизе), и предлагает установить; после установки перезапускается. Проверка только в релизных сборках.

## Голос и видео в webview

Проверено по документации и issue Tauri/wry на октябрь 2026 (живьём — только Windows):

| Платформа          | Микрофон и камера                                                                                                                | Демонстрация экрана                                                                                                                   |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Windows (WebView2) | работают                                                                                                                         | `getDisplayMedia` есть, но выбор окна/экрана должен показать хост — пока не реализовано, кнопка демонстрации в приложении не работает |
| macOS (WKWebView)  | работают с entitlements камеры и микрофона (`Entitlements.plist`)                                                                | на macOS 14+ нужен обработчик разрешения display-capture на стороне оболочки — пока не реализовано                                    |
| Linux (WebKitGTK)  | зависит от сборки WebKitGTK: в Ubuntu 24.04 / 26.04 пакет собран без WebRTC — `RTCPeerConnection` отсутствует, голос не работает | нет                                                                                                                                   |

Итого для v0.15: текст, уведомления, трей и прочее — везде; голос — Windows и macOS; демонстрация экрана из приложения — пока нет (пользуйтесь браузером). Это отмечено в `TODO.md` как отложенное с причинами.

Голосовые сообщения (v0.18) записываются через `MediaRecorder` того же webview. Где его нет или он не пишет ни Opus, ни AAC (возможно, на Linux), кнопка микрофона в поле ввода не показывается, а слушать голосовые можно везде. В самом приложении запись пока не проверялась — только в браузере (Chromium, e2e).

## Разработка

```bash
pnpm install
# Rust и зависимости Tauri: https://v2.tauri.app/start/prerequisites/
pnpm --filter @chinchi/desktop app:dev          # Vite на :5174 + окно приложения
pnpm --filter @chinchi/desktop app:build        # установщики в apps/desktop/src-tauri/target/release/bundle
```

- Вход приложения — `apps/web/desktop.html` → `src/desktop/main.tsx`; сборка `pnpm --filter @chinchi/web build:desktop` кладёт её в `apps/web/dist-desktop/index.html`, откуда её берёт Tauri. Маршруты — hash-history (`#/channels/...`): оболочка отдаёт один HTML-файл.
- Всё, что веб-приложение умеет просить у оболочки, описано интерфейсом `Shell` (`apps/web/src/features/shell/shell.ts`); Tauri-реализация — `src/desktop/tauri-shell.ts`, в тестах — `createFakeShell()`. Новая возможность оболочки добавляется туда, а не прямым импортом `@tauri-apps/*` из компонентов.
- Права webview перечислены в `apps/desktop/src-tauri/capabilities/default.json`; CSP приложения — в `tauri.conf.json` (`csp` для сборки, `devCsp` для dev-сервера Vite с его inline-скриптами).
- Отладка webview: запустите dev с `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9229` (Windows) и подключайтесь DevTools или Playwright (`chromium.connectOverCDP`).

## Релиз

Тег `vX.Y.Z` собирает приложение на трёх раннерах GitHub (`release.yml`, job `desktop`) и добавляет установщики и `latest.json` в тот же релиз, что и файлы сервера. Версия в `apps/desktop/src-tauri/tauri.conf.json` и `Cargo.toml` должна совпадать с тегом — workflow это проверяет. Для подписи обновлений в секретах репозитория нужны `TAURI_SIGNING_PRIVATE_KEY` (содержимое приватного ключа) и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` (пустой, если ключ без пароля); публичный ключ зашит в `tauri.conf.json`. Без секрета workflow всё равно соберёт и опубликует установщики, но без пакетов обновлений и `latest.json`: приложение из такого релиза не найдёт обновлений и будет ждать, пока их не станет в следующем — тогда оно обновится само. Пару ключей делает `pnpm --filter @chinchi/desktop tauri signer generate -w ~/.tauri/chinchi-updater.key`; потеря приватного ключа означает, что установленные приложения перестанут принимать обновления — его нужно хранить так же бережно, как `SECRETS_KEY` сервера.
