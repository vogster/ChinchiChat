## ✅ Фаза 15 — Шифрование (v0.8)

Сначала модель угроз и дизайн, потом реализация. Текстовые каналы серверов остаются шифрованными только на транспорте (TLS): там нужны поиск, модерация, боты и история для новых участников.

- [x] Модель угроз и дизайн (`docs/encryption.md`): от кого защищаем (утечка БД и бэкапов, любопытный администратор инстанса, перехват в сети), что сервер видит всегда (метаданные: кто, кому, когда), что теряется в E2EE-чатах (поиск на сервере, превью ссылок, боты, автомодерация)
- [x] Spike: библиотека MLS для браузера и React Native — выбрана ts-mls 1.6.4 (группа из 4 устройств, удаление, сохранение состояния, ключ звонка из exporter, 50 устройств за ~1 с; аудита нет — за своим интерфейсом), LiveKit E2EE — через RTCRtpScriptTransform (проверка в webview — _отложено: до фазы Desktop_)
- [x] `packages/e2ee`: обёртка над ts-mls (устройства, группы, сохранение состояния, ключ звонка) со сценарными тестами: отправитель, удаление, недоверенное устройство, гонка коммитов (откат — из сохранённой копии), подмена шифротекста (векторы RFC 9420 — _отложено: их проверяет сама ts-mls, у нас — сценарии поверх неё_)
- [x] Сервер: устройства и KeyPackage, служба доставки MLS (порядок коммитов, Welcome, зашифрованные сообщения), тип беседы «Зашифрованная беседа» (флаг `encrypted` у ЛС и групп; коммит — только для текущей эпохи, иначе `STALE_EPOCH`; Welcome — только своему устройству; сообщения — `ciphertext` без текста, без упоминаний, автомодерации и превью)
- [x] Веб: ключи устройства в IndexedDB, создание зашифрованной беседы (из карточки профиля), чтение и отправка, добавление новых и удаление отозванных устройств участников, «ждём, пока впустят это устройство»; браузер становится устройством сразу при входе; e2e — два человека в настоящем Chromium, сервер хранит только шифротекст (предупреждения о новых устройствах — сделано там же, с кодами безопасности)
- [x] Одна зашифрованная беседа на пару людей: «Зашифрованная беседа» в профиле открывает уже начатую (ключ пары `e2ee:a:b` в `dm_key`, одновременные открытия — одна беседа)
- [x] Звонки в зашифрованных беседах: LiveKit E2EE, ключ из MLS exporter, смена ключа при смене состава (слот ключа — эпоха; e2e — видео собеседника декодируется только с ключом беседы)
- [x] Файлы в зашифрованных беседах шифруются на клиенте до загрузки (AES-256-GCM, ключ — внутри MLS-сообщения; на сервере — `encrypted`/`application/octet-stream`; картинки показываются после проверки сигнатуры; вычистка EXIF — сделано в фазе 16)
- [x] Правка и ответы в зашифрованных беседах (каждая правка — новое MLS-сообщение, файлы сохраняются; цитату ответа берём из расшифрованного на устройстве), зашифрованные группы из диалога «Новая группа»; перед отправкой состав MLS-группы сверяется с участниками — вышедший не получит следующее сообщение, даже если беседу ещё никто не открывал
- [x] Шифрование хранения: SSE в RustFS (KMS), инструкция по шифрованию дисков (мастер-ключ `S3_KMS_MASTER_KEY` в `.env`; ключ KMS сервер создаёт сам через admin API RustFS; e2e и CI — с шифрованием)
- [x] Проверка собеседника: коды безопасности, предупреждение о новом устройстве или смене ключа; свои устройства шифрования — в «Настройки → Устройства» с удалением (60 цифр из ключей устройств обоих; «Коды совпали» действует, пока не изменятся устройства; новое устройство своё или собеседника — предупреждение; e2e — коды у двоих совпадают; QR-код — _отложено: этап 2_)
